🚀 Azure Discovery Tool - Quick Start Guide

Welcome! This tool automatically discovers all your Azure resources, dependencies, and configurations for migration planning.

100% READ-ONLY: This tool only reads your Azure environment. It will NOT create, modify, or delete anything.

📋 Prerequisites

  • Azure CLI - Must be installed and logged in
  • Python 3.11 - Bundled version included in tool\python\
  • Azure Reader Role - Minimum permission required

🎯 How to Run

1 Login to Azure
az login

This opens your browser for authentication. Login with your Azure account.

2 Run the Discovery Tool

Option 1 (Recommended): Double-click the file

run.cmd

Option 2: Run from PowerShell

powershell -ExecutionPolicy Bypass -File run_discovery.ps1

Note: The script is not digitally signed. Use run.cmd to bypass execution policy.

3 Wait for Discovery to Complete

The tool will scan all your Azure subscriptions. This may take 5-15 minutes depending on the number of resources.

4 Open the Reports

All reports are saved in the discovery_output\ folder. Double-click the HTML file to view in your browser.

📊 Generated Reports

📄 HTML Report

Interactive web report with tabs, charts, and dependency graphs

File: azure_discovery_report_*.html

📊 Excel Report

Detailed spreadsheet with all resources and configurations

File: azure_discovery_report_*.xlsx

💾 JSON Data

Raw discovery data for custom processing or automation

File: discovery_data_*.json

⚙️ Configuration (Optional)

Edit config.json to customize the discovery:

{ "auth_method": "default", "subscription_ids": [], // Leave empty to scan all "scan_code": true, // Scan Git repositories "scan_network_flows": true, // Analyze network topology "deep_dependency_analysis": true // Find all dependencies }

🔗 Azure DevOps Git Repositories (Optional)

To scan code repositories for application dependencies:

  1. Create a Personal Access Token (PAT) in Azure DevOps with Code (Read) permission
  2. Update config.json with your organization and PAT
  3. Specify repositories with optional branch selection
  4. The tool will automatically scan and analyze your code
"azure_devops": { "organization": "YOUR_ORG_NAME", "pat_token": "YOUR_PERSONAL_ACCESS_TOKEN", "projects": [ { "project_name": "MyProject", "repositories": [ {"name": "webapp", "branch": "main"}, {"name": "api", "branch": "develop"}, "shared-lib" // Uses default branch ] } ] }

❓ Troubleshooting

⚠️ "Azure CLI not found"

Install Azure CLI from: https://aka.ms/installazurecliwindows

⚠️ "Python not found"

The bundled Python should work automatically. If not, install Python 3.11 from: https://www.python.org/downloads/

⚠️ "No resources discovered"

Make sure you're logged in to the correct Azure account and have at least Reader role access.

🔒 Security & Privacy

✅ What's Included in Reports

  • Resource names, types, and locations
  • Network configurations (VNets, subnets, NSGs)
  • Dependency relationships
  • Configuration metadata

🔐 What's NOT Included (Protected)

  • Connection strings (shown as ***REDACTED***)
  • Passwords and secrets
  • API keys and certificates
  • Actual data from databases or storage

📁 File Structure

Discovery/ ├── azure_discovery.py ← Main Python script (single file) ├── run_discovery.ps1 ← PowerShell runner (easy to use) ├── config.json ← Configuration file ├── requirements.txt ← Python dependencies ├── discovery_output/ ← All reports saved here │ ├── azure_discovery_report_*.html │ ├── azure_discovery_report_*.xlsx │ ├── discovery_data_*.json │ └── sample_*.html ← Sample reports (reference) └── tool/python/ ← Bundled Python (portable)

💡 Tips

  • First Time Run: The tool will create a default config.json if it doesn't exist
  • Multiple Runs: You can run the tool multiple times - each run creates new timestamped reports
  • Share Reports: HTML reports are standalone files - safe to email or share
  • Filter Subscriptions: Edit config.json to scan specific subscriptions only
